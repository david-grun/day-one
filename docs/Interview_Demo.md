# Four-to-five-minute HR-led demonstration

Before the interview, start the app, verify `/api/health`, sign in as Mara Santos, and confirm saved records load. Confirm the actual Power BI report, snapshot timestamp, and permitted embed access if configured. Keep the local database backed up and the Desktop report available. Do not claim a verified embed when only the setup state exists.

1. **30 seconds — Home.** Show an urgent hire with a missing task, its owner, and a useful next action. Explain that the application coordinates first-day preparation across teams.
2. **60 seconds — New hire.** Create a clearly fictional Software Engineer or Sales Associate. Inspect the checklist preview, calendar-day deadlines, manager/IT/HR ownership, and parallel work. Save and open the generated plan. Explain that it is saved as a snapshot, and retries cannot create duplicate work.
3. **45 seconds — Blocked example.** Open **Eli Ramos**, labeled as overdue IT preparation waiting for manager requirements. Explain that HR sees the accountable manager and IT dependency without completing their work on their behalf. This is seeded fictional example history.
4. **60 seconds — Last HR task.** Open **Sofia Dela Cruz**, labeled as the HR walkthrough. Earlier IT and manager completions are seeded. Complete the remaining joining-instructions task as Mara. Observe that full required completion opens **Awaiting HR review**.
5. **45 seconds — Final review.** Inspect existing completion evidence, confirmed requirements, assigned reviewer, and preparation version. Approve readiness. The recorded name/time/version explain accountability. Optional buddy work can remain unfinished.
6. **45 seconds — Analytics.** Show updated live readiness and review counts, an overdue team chart with its record links, and department completion. Open the actual Power BI view when configured. Explain that it uses an explicit published snapshot and refresh procedure. If access is unavailable, show the export and Desktop path and identify embedding as unverified.

Account switching is optional. For a permissions demonstration, sign into a real IT or manager demo account and use its own queue. The main HR story does not require changing roles or letting HR impersonate another team.

Useful explanation: “The manager confirms what access is needed. IT prepares it. HR reviews the preparation before the hire becomes ready. If the requirements change, the earlier approval becomes invalid and affected work returns for checking. A transaction keeps those facts consistent.”

The app replaces hand-built preparation checklists with template generation, separate status consolidation with shared records, and undocumented approval with a versioned sign-off history. HR gains an attention/review queue; IT and managers gain owned work with dependency context. Readiness, overdue ownership and review waiting measure the coordination process. Reduced chasing and time savings remain hypotheses until evaluated with practitioners; task duration includes waiting and is not labor time.

After the primary walkthrough, a reasoned correction on an approved hire can demonstrate history and approval invalidation. Use a backup or an explicit demo reset before repeating the seeded sequence. Fresh hires created through the UI remain when demo records are reset.
